# 韧性手册（agent 调用容错 + 并发自适应）

> **何时读本文件**：agent 结果/通知含 `429 / 5xx / rate limit / 速率限制 / terminated early / crashed` 或**无任何产出文件**时（判为基础设施失败，区别于业务 PASS/FAIL）。业务失败（测试 FAIL / 冒烟 FAIL）不读本文件，走修正循环 + 失败分类路由。

## 一、区分两类失败

- **业务失败**（测试 FAIL / 冒烟 FAIL）→ 修正循环 + 失败分类路由（不读本文件）
- **基础设施失败**（API 429 / 超时 / agent 崩溃 / 无产出）→ 本文件退避重试 + 触发并发自适应

## 二、退避重试（区分失败类型；重试的是同一调度动作、不污染业务状态）

### ① 429 / 速率限制——先判断瞬时还是长期（长期可能等几小时，不能在 session 里死等）

- **短期**：退避重试（60s 间隔，最多 3 次）判断是否瞬时。日志 `⏳ 限流，60s 后重试（第N次）` + 触发「并发自适应」降档。
- **长期**（3 次仍 429 = 账户级限速，可能等几小时）：**不死等、不空耗 session**，**记中断点 + 优雅暂停**：
  - main-log 记 `⏸️ 长期限流暂停，dev-plan 状态已落盘（🔳/🔄），服务恢复后说"继续"`
  - 向用户报告「限流了，可能要等几小时，恢复后告诉我继续」
- **恢复续跑**：用户（几小时后）说"继续" → 走「压缩后恢复机制」(`handbook/recovery.md`) 按 dev-plan 状态精确续（韧性第1层：⏳开发 / 🔄重做 / 🔳续测）。

> 即：**长期限流 = 一种"中断"**，用中断恢复机制处理（记状态 + 暂停 + 恢复续），而非 master 在 session 里空耗几小时。

### ② 其他基础设施失败（崩溃 / 超时 / 无产出，可能非临时）——指数退避，最多 3 次

```
失败 → 等待 30s  → 重试
失败 → 等待 60s  → 重试
失败 → 等待 120s → 重试
3 次仍失败 → ⚠️ 告警 + 向用户报告（不无限耗）
```

日志：`⏳ agent 失败重试（第N次，退避Xs）：{原因}`。

## 三、并发自适应（遇 429 自动降并发，慢慢干）

**原理**：限流时宁可慢、不可卡死。master 维护**运行时有效并发**（初始 = 配置默认值），检测到 429 自动降档，继续慢跑。

**运行时变量**（master 内存，非改配置文件）：
- `eff_PARALLEL` = MAX_PARALLEL（初始 3）
- `eff_BATCH` = BATCH_SIZE（初始 = 最大化，即取全部就绪）

**429 触发降档**（每次降一档，写日志）：
```
⬇️ 限流降并发：eff_PARALLEL 3→1（五维全串行）/ eff_BATCH 最大化→3→2→1（开发降并发），继续慢跑不卡死
```
- eff_PARALLEL 档位：3 → 1（五维从分批降到全串行）
- eff_BATCH 档位：最大化 → 3 → 2 → 1（开发从全量降到逐任务）
- **降到最低仍限流**：agent 启动强制加间隔（如 30s），彻底串行慢跑
- 降档后用 eff_* 继续调度（取批/分批/测试并发都用 eff_*，不用配置原值）

**不自动升档**（首版保守防震荡）：停在降后值，日志提示当前 eff_*；用户可手动调回配置值。
